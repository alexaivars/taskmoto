# Taskmoto UI design principles

Make logging and reviewing work time fast, easy, and unobtrusive. Apply these principles to the interface and its wording. The [product decision](decisions/defining-taskmoto-as-worklog-and-time-reporting-app.md) defines Taskmoto's purpose, audience, privacy, and access requirements.

1. **Build for our purpose.** Give each view a clear job and an easy-to-find main action. Choose useful defaults without forcing one way to work. Add options only when they serve Taskmoto's purpose and justify the effort they add.

2. **Start simple, grow more powerful.** Let people begin without setup. Offer more capable ways to work as their needs grow. Make these capabilities easy to find and use through familiar patterns, while keeping everyday use simple.

3. **Respect people's time.** Reduce steps, decisions, waiting, and interruptions. Prioritize fast capture; let people organize later. Offer help when they review or report their work, without interrupting capture.

4. **Make intent clear.** Use familiar controls and plain language that people understand on first use. Omit visible labels only when the meaning remains clear. Always give controls accessible names for screen readers. Keep shortcuts optional.

5. **Keep the work in focus.** Use text, spacing, and alignment to organize information. Use color, borders, and icons to convey meaning. Give supporting controls less emphasis while keeping them readable and easy to find. Avoid excessive empty space.

6. **Be consistent.** Give equivalent actions the same names, appearance, and behavior. Keep their placement predictable across layouts. Change a pattern only to communicate a meaningful difference.

7. **Make outcomes clear.** Show routine success through the result itself. When a problem needs attention, explain it and give a clear next step. Preserve people's work when something goes wrong.

8. **Keep simplicity as we grow.** Review the whole view when adding something. Improve existing controls before adding more. Combine controls that serve the same purpose and remove repetition.

9. **Make quality part of every choice.** Build reliable behavior and refine visual details. Support keyboard use and screen readers, with readable contrast and visible keyboard focus. Check designs and wording in the working app with realistic content. Make the core experience excellent before expanding it.
